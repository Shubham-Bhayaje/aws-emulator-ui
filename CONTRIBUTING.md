# Contributing to AWS Emulator UI

Thank you for your interest in contributing to AWS Emulator UI! This is an open-source, community-driven project providing an unofficial web management console for the official [AWS Emulator (`aws/aws-emulator`)](https://github.com/aws/aws-emulator).

Contributions of all types are welcome: new service integrations, UI improvements, bug reports, and documentation enhancements.

---

## Code of Conduct

Please be respectful, constructive, and helpful when participating in discussions and submitting pull requests.

---

## Development Setup

1. **Prerequisites**:
   - Node.js (v20 or newer)
   - Docker Desktop or Docker engine
   - Git

2. **Fork and Clone**:
   ```bash
   git clone https://github.com/YOUR_USERNAME/aws-emulator-ui.git
   cd aws-emulator-ui
   npm install
   ```

3. **Start the AWS Emulator**:
   Ensure the official AWS Emulator container is running locally on port 9297:
   - On Linux/macOS/WSL: `./scripts/emulator.sh start`
   - On Windows (PowerShell):
     ```powershell
     New-Item -ItemType Directory -Force "$env:USERPROFILE\.aws\emulator"
     $port = 9297
     docker run -d --rm --memory=2g --memory-swap=2g -p "127.0.0.1:${port}:${port}" -v "$env:USERPROFILE\.aws\emulator:/home/emulator/.aws/emulator" aws-emulator -p $port --telemetry off
     ```

4. **Run the UI Dev Server**:
   ```bash
   npm run dev
   ```
   Open `http://127.0.0.1:3000` in your browser.

---

## Architectural Guidelines

- **Zero Cloud Costs**: All requests must target the local emulator (`https://127.0.0.1:9297`). Do not add dependencies that require real AWS credentials.
- **Server Actions & Server Components**: Keep AWS SDK calls on the server side (Server Actions in `actions.ts` or Server Components). Do not expose AWS credentials to client components.
- **TLS Trust**: Use the self-signed CA cert (`ca.pem`) generated by the emulator via `NODE_EXTRA_CA_CERTS`. Do not disable TLS validation (`rejectUnauthorized: false`).
- **Cloudscape UI Consistency**: Maintain pixel-perfect visual fidelity with official AWS Console aesthetics (dark `#000716` header, standard table layouts, breadcrumbs, and AWS architecture icons).

## Submitting a Pull Request

1. Create a feature branch from `main`:
   ```bash
   git checkout -b feat/your-feature-name
   ```
2. Verify your changes pass linting and build:
   ```bash
   npm run lint
   npm run build
   ```
3. Commit with a clear, descriptive message:
   ```bash
   git commit -m "feat(dynamodb): add pagination to item explorer"
   ```
4. Push to your fork and open a Pull Request against `main`. Include a brief description of the changes and screenshots of any UI updates.

---

## Reporting Issues

If you encounter bugs or want to request a new AWS service screen, please open an issue using the templates in the GitHub repository.
