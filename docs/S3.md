# Amazon S3 (Simple Storage Service) Guide

Amazon Simple Storage Service (Amazon S3) is an object storage service offering industry-leading scalability, data availability, security, and performance. Organizations of all sizes can use Amazon S3 to store and protect any amount of data for use cases such as data lakes, cloud-native applications, and mobile apps. S3 stores data as objects within resources called buckets, which can be managed with granular access permissions, automated lifecycle transitions, and encryption controls. Use Amazon S3 whenever your application needs reliable, cost-effective storage for unstructured data such as files, images, videos, backups, and analytical datasets.

---

## Key Concepts

### 1. Buckets
A bucket is a fundamental container for objects stored in Amazon S3. Every bucket has a globally unique name across all AWS accounts and is created within a specific AWS Region.
- *Example*: A bucket named `production-web-assets-2026` hosted in `us-east-1` that stores static images and videos.

### 2. Objects
An object is the fundamental entity stored in Amazon S3, consisting of object data (the file itself) and metadata (key-value pairs describing the file, such as `Content-Type` and size).
- *Example*: An object with key `images/logo.png`, MIME type `image/png`, and size `24.5 KB` stored inside a bucket.

### 3. S3 Bucket Versioning
A mechanism to keep multiple variants of an object in the same bucket, protecting data from unintended overwrites and accidental deletions.
- *Example*: Overwriting `documents/contract.pdf` generates a new current version while retaining previous version IDs for point-in-time recovery.

### 4. Storage Classes
Tiered storage options tailored to different data access patterns, retention requirements, and cost profiles (e.g., Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant Retrieval, Glacier Flexible Retrieval, Glacier Deep Archive).
- *Example*: Keeping active user uploads in `Standard` storage and transitioning monthly database dumps to `Glacier Flexible Retrieval` after 90 days.

### 5. Default Encryption & AWS KMS
Automated server-side encryption applied to every new object written to a bucket, using either Amazon S3 managed keys (SSE-S3) or customer-managed AWS KMS keys (SSE-KMS).
- *Example*: Enforcing SSE-KMS with key `arn:aws:kms:us-east-1:000000000000:key/1234abcd` and enabling S3 Bucket Keys to minimize KMS API request charges.

### 6. Block Public Access & Bucket Policies
Security guardrails that prevent unauthorized public exposure of your buckets and objects through access control lists (ACLs) or resource-based JSON bucket policies.
- *Example*: A bucket policy granting read-only access to an IAM role while Block Public Access prevents accidental public anonymous downloads.

### 7. Static Website Hosting
Hosting a static website directly from an Amazon S3 bucket with an index document (`index.html`) and custom error document (`error.html`).
- *Example*: Hosting a React single-page application built as static HTML, CSS, and JS files served through the S3 website endpoint.

## Console Walkthrough and Verified AWS CLI Commands

Every action below is fully implemented in this console and tested against the local AWS emulator.

### 1. View Buckets Inventory (`/s3`)
The main buckets table lists all buckets in your account with Name, AWS Region, Access status, and Creation date. A search bar allows filtering by bucket name, and buttons enable viewing details, copying ARNs, emptying buckets, and deleting buckets.
- **Matching AWS CLI Command**:
```bash
aws s3api list-buckets \
  --endpoint-url https://127.0.0.1:9297
```

### 2. Create a Bucket (`/s3/create`)
A form to provision a new bucket:
- **General configuration**: Enter a globally unique bucket name (e.g., `my-learning-bucket-2026`) and select an AWS Region.
- **Object Ownership**: Choose between ACLs disabled (recommended) or ACLs enabled.
- **Block Public Access**: Enable master `Block all public access` or toggle specific ACL and policy guardrails.
- **Bucket Versioning**: Choose `Enable` or `Disable`.
- **Default Encryption**: Choose `Amazon S3 managed keys (SSE-S3)` or `AWS Key Management Service keys (SSE-KMS)` with KMS key selection from your account.

- **Matching AWS CLI Command**:
```bash
aws s3api create-bucket \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```

### 3. Bucket Details & Tabs (`/s3/[bucket]`)
Clicking any bucket opens its details page with 6 tabs:
- **Objects**: Browse folder prefixes, upload files, create folders, download objects, copy keys, and toggle version history.
- **Properties**: Overview, Bucket Versioning, Default encryption, Server access logging, Static website hosting, Bucket tags, and Transfer acceleration.
- **Permissions**: Block Public Access settings, Bucket policy (JSON editor), Object Ownership, and CORS configuration.
- **Metrics**: Total bucket size and object count.
- **Management**: Lifecycle rules (storage class transitions and expiration).
- **Access Points**: S3 Access points configured for this bucket.

- **Describe Bucket / Head Bucket**:
```bash
aws s3api head-bucket \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```

### 4. Upload Objects & Manage Folders (`/s3/[bucket]/upload`)
Upload files through drag-and-drop or file selector, specify destination folder prefixes, choose storage classes, and configure tags and encryption overrides.
- **Upload File**:
```bash
aws s3api put-object \
  --bucket my-learning-bucket-2026 \
  --key sample.txt \
  --body sample.txt \
  --endpoint-url https://127.0.0.1:9297
```
- **List Objects**:
```bash
aws s3api list-objects-v2 \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```
- **Download Object**:
```bash
aws s3api get-object \
  --bucket my-learning-bucket-2026 \
  --key sample.txt \
  downloaded-sample.txt \
  --endpoint-url https://127.0.0.1:9297
```

### 5. Configure Bucket Versioning
Protect objects from accidental overwrites and deletions by enabling versioning.
- **Enable Versioning**:
```bash
aws s3api put-bucket-versioning \
  --bucket my-learning-bucket-2026 \
  --versioning-configuration Status=Enabled \
  --endpoint-url https://127.0.0.1:9297
```
- **Inspect Versioning Status**:
```bash
aws s3api get-bucket-versioning \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```
- **List Object Versions**:
```bash
aws s3api list-object-versions \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```

### 6. Configure Default Encryption
Ensure all objects written to the bucket are automatically encrypted at rest.
- **Set SSE-S3 Default Encryption**:
```bash
aws s3api put-bucket-encryption \
  --bucket my-learning-bucket-2026 \
  --server-side-encryption-configuration '{"Rules": [{"ApplyServerSideEncryptionByDefault": {"SSEAlgorithm": "AES256"}}]}' \
  --endpoint-url https://127.0.0.1:9297
```
- **Get Encryption Configuration**:
```bash
aws s3api get-bucket-encryption \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```

### 7. Manage Block Public Access Settings
Configure bucket-level public access restrictions.
- **Enable Block All Public Access**:
```bash
aws s3api put-public-access-block \
  --bucket my-learning-bucket-2026 \
  --public-access-block-configuration "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true" \
  --endpoint-url https://127.0.0.1:9297
```
- **Get Public Access Block**:
```bash
aws s3api get-public-access-block \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```

### 8. Bucket Policy (JSON Permissions)
Attach an IAM resource policy to define granular access control.
- **Apply Bucket Policy**:
```bash
aws s3api put-bucket-policy \
  --bucket my-learning-bucket-2026 \
  --policy '{"Version":"2012-10-17","Statement":[{"Sid":"PublicRead","Effect":"Allow","Principal":"*","Action":"s3:GetObject","Resource":"arn:aws:s3:::my-learning-bucket-2026/*"}]}' \
  --endpoint-url https://127.0.0.1:9297
```
- **Get Bucket Policy**:
```bash
aws s3api get-bucket-policy \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```
- **Delete Bucket Policy**:
```bash
aws s3api delete-bucket-policy \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```

### 9. Static Website Hosting
Configure your bucket to serve a static website.
- **Enable Static Website Hosting**:
```bash
aws s3api put-bucket-website \
  --bucket my-learning-bucket-2026 \
  --website-configuration '{"IndexDocument": {"Suffix": "index.html"}, "ErrorDocument": {"Key": "error.html"}}' \
  --endpoint-url https://127.0.0.1:9297
```
- **Get Website Configuration**:
```bash
aws s3api get-bucket-website \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```
- **Disable Website Hosting**:
```bash
aws s3api delete-bucket-website \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```

### 10. Lifecycle Configuration
Automate storage tiering and object expiration.
- **Apply Lifecycle Rules**:
```bash
aws s3api put-bucket-lifecycle-configuration \
  --bucket my-learning-bucket-2026 \
  --lifecycle-configuration '{"Rules": [{"ID": "ExpireLogs30Days", "Status": "Enabled", "Filter": {"Prefix": "logs/"}, "Expiration": {"Days": 30}}]}' \
  --endpoint-url https://127.0.0.1:9297
```
- **Get Lifecycle Configuration**:
```bash
aws s3api get-bucket-lifecycle-configuration \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```

### 11. Copy, Tag, and Delete Objects
Manage individual object attributes and deletion.
- **Copy Object**:
```bash
aws s3api copy-object \
  --bucket my-learning-bucket-2026 \
  --copy-source my-learning-bucket-2026/sample.txt \
  --key sample-backup.txt \
  --endpoint-url https://127.0.0.1:9297
```
- **Set Object Tags**:
```bash
aws s3api put-object-tagging \
  --bucket my-learning-bucket-2026 \
  --key sample.txt \
  --tagging 'TagSet=[{Key=Environment,Value=Production}]' \
  --endpoint-url https://127.0.0.1:9297
```
- **Delete Object**:
```bash
aws s3api delete-object \
  --bucket my-learning-bucket-2026 \
  --key sample.txt \
  --endpoint-url https://127.0.0.1:9297
```

### 12. Empty and Delete Bucket
Safely remove all objects and de-provision the bucket.
- **Delete Bucket**:
```bash
aws s3api delete-bucket \
  --bucket my-learning-bucket-2026 \
  --endpoint-url https://127.0.0.1:9297
```

## Hands-On Exercises for Beginners

### Exercise 1: Create a Bucket and Upload Objects
1. Open **S3** from the top navigation search bar (`Alt + S`) or the services menu.
2. Click **Create bucket**.
3. Name your bucket `lab-demo-storage-yourname` (lowercase letters and numbers).
4. Leave Block Public Access enabled and click **Create bucket**.
5. Click your new bucket in the list to open its details view.
6. Click **Upload**, drag a test text file into the drop zone, and click **Upload**.
7. Confirm that your uploaded file appears in the objects table with its size and storage class.

### Exercise 2: Enable Versioning and Test Overwrites
1. Inside your bucket, navigate to the **Properties** tab.
2. In the **Bucket Versioning** card, click **Edit**.
3. Select **Enable** and click **Save changes**.
4. Return to the **Objects** tab and upload another file with the exact same name as your first file.
5. In the toolbar, toggle **Show versions** to `ON`.
6. Verify that both versions of your file are visible with unique Version IDs.

### Exercise 3: Configure Default Encryption with KMS
1. On the **Properties** tab of your bucket, locate **Default encryption** and click **Edit**.
2. Select **AWS Key Management Service keys (SSE-KMS)**.
3. In the KMS key selector, choose your customer managed key from the dropdown (or select `aws/s3`).
4. Enable **Bucket Key** to optimize encryption cost.
5. Click **Save changes** and verify the encryption status card reflects `SSE-KMS`.

### Exercise 4: Host a Static Website
1. On the **Permissions** tab, click **Edit** under **Block public access (bucket settings)**.
2. Uncheck **Block all public access**, acknowledge the warning checkbox, type `confirm`, and save.
3. Under **Bucket policy**, click **Edit** and paste a policy allowing `s3:GetObject` on `arn:aws:s3:::<your-bucket>/*`.
4. On the **Properties** tab, scroll to **Static website hosting** and click **Edit**.
5. Select **Enable**, enter `index.html` as the index document, and save.
6. Upload an `index.html` file to the root of your bucket and verify the website endpoint URL is generated.

## Emulator Limitations

1. **Path-Style Addressing Required**:
   - The emulator does not resolve virtual-hosted bucket DNS subdomains (`<bucket>.s3.amazonaws.com`). The AWS SDK client is configured with `forcePathStyle: true` against `https://127.0.0.1:9297/<bucket>`.
2. **S3Control Virtual-Host Routing**:
   - Account-level S3 operations (`aws s3control`) attempt to connect to `<account-id>.127.0.0.1:9297`, which is unsupported on standard loopback IP sockets. S3 Access Points and S3 Account Block Public Access utilize simulated persistent configuration in the console.
3. **Non-Empty Bucket Deletion**:
   - The emulator enforces strict AWS deletion semantics: a bucket with active objects or version tombstones cannot be deleted. Use the **Empty** button in the console first to purge all versions before calling delete.

## Common Errors and Troubleshooting

1. **BucketNotEmpty: The bucket you tried to delete is not empty**
   - *Cause*: Attempting to delete a bucket that still contains objects or version markers.
   - *Fix*: Select the bucket on `/s3`, click **Empty**, type `permanently delete`, and then click **Delete**.

2. **BucketAlreadyExists: The requested bucket name is not available**
   - *Cause*: Bucket names must be globally unique across all accounts in the emulator.
   - *Fix*: Choose a different bucket name by appending unique numbers or your initials.

3. **AccessDenied: Access Denied**
   - *Cause*: The active IAM identity lacks `s3:PutObject`, `s3:GetObject`, or `s3:CreateBucket` permissions, or Block Public Access is blocking an action.
   - *Fix*: Use the top navigation identity switcher to switch to `Administrator`, or verify the bucket policy.
