# Amazon Simple Email Service (SES) Console Guide

Amazon Simple Email Service (SES) is a cloud-based email sending and receiving service designed to help digital marketers and application developers send marketing, notification, and transactional emails. It eliminates the operational complexity and cost of building and maintaining an in-house email infrastructure, complex SMTP servers, and IP reputation management. You should use Amazon SES when your applications need to reliably send automated transactional messages (such as password resets, order confirmations, and receipts), bulk marketing campaigns, or receive inbound email directly into cloud workflows.

---

## 1. Key Concepts

### Verified Identities
An identity is a domain or individual email address that you own and verify with Amazon SES to authorize email sending.
- *Example*: Verifying `notifications@example.com` or the entire domain `example.com` so your web backend can send password reset links on behalf of your brand.

### Easy DKIM (DomainKeys Identified Mail)
An authentication method that adds a cryptographic digital signature to email headers. Receiving mail servers verify this signature against public keys published in your domain DNS to confirm the message was not altered or spoofed in transit.
- *Example*: Publishing 3 CNAME DNS records generated by SES (`<token>._domainkey.example.com`) to allow mailbox providers like Gmail and Outlook to authenticate your outbound messages.

### Custom MAIL FROM Domain
The email address specified in the SMTP envelope that receiving mail servers inspect during SPF (Sender Policy Framework) evaluation and bounce reporting.
- *Example*: Setting a custom subdomain `mail.example.com` with MX and SPF TXT records so the envelope domain matches your sending domain, achieving full DMARC alignment.

### Configuration Sets
Groups of rules and event destinations applied to outbound messages to capture operational telemetry such as delivery attempts, opens, clicks, bounces, and complaints.
- *Example*: Attaching a configuration set named `transactional-alerts` that streams real-time bounce and complaint notifications into an Amazon SNS topic or Amazon CloudWatch Logs.

### Email Templates
Reusable transactional email structures containing subject lines, HTML bodies, and plain-text fallback content with Mustache replacement variables (`{{name}}`).
- *Example*: A `WelcomeTemplate` with HTML `<h1>Welcome, {{name}}!</h1>` where dynamic user values are substituted when calling `SendTemplatedEmail`.

### Suppression List
An account-level protective blocklist of recipient addresses that have previously produced hard bounces or spam complaints. SES automatically suppresses outbound sends to these addresses to preserve your sender reputation.
- *Example*: Adding an invalid address `bounce@example.com` to the suppression list so subsequent application attempts to message it are blocked before sending.

### SMTP Credentials
Dedicated IAM credentials formatted specifically for standard SMTP mail transfer agents, where the SMTP password is mathematically computed from an IAM secret access key using HMAC-SHA256 (RFC 2104).
- *Example*: Configuring a WordPress website, Postfix daemon, or Node.js Nodemailer client with host `127.0.0.1`, port `587`, and SES SMTP credentials.

## 2. Console Walkthrough & Matching AWS CLI Commands

Every action below is verified and supported by the local AWS emulator engine.

### A. Account Dashboard (`/ses/dashboard`)
Displays 24-hour rolling sending limits, max send rates, sandbox/production status, and deliverability reputation gauges (bounce rate and complaint rate).

**AWS CLI Equivalents:**
```bash
# Check 24-hour send quota and max send rate
aws ses get-send-quota

# Query historical sending data points and statistics
aws ses get-send-statistics

# Inspect account enforcement status and suppression list configuration
aws sesv2 get-account
```

### B. Verified Identities (`/ses/identities`)
Displays all registered email addresses and domains with verification status, Easy DKIM status, and custom MAIL FROM configuration.

**AWS CLI Equivalents:**
```bash
# List all verified email and domain identities
aws ses list-identities

# Start email address verification
aws ses verify-email-identity \
  --email-address "sender@example.com"

# Check verification status for registered identities
aws ses get-identity-verification-attributes \
  --identities "sender@example.com" "example.com"

# Delete an identity
aws ses delete-identity \
  --identity "sender@example.com"
```

### C. Create Identity Wizard (`/ses/identities/create`)
Walks through verifying an email address or an entire domain, enabling Easy DKIM with RSA 2048-bit signing, and configuring custom MAIL FROM subdomains.

**AWS CLI Equivalents:**
```bash
# Verify domain identity and generate verification token
aws ses verify-domain-identity \
  --domain "example.com"

# Generate Easy DKIM tokens for the domain
aws ses verify-domain-dkim \
  --domain "example.com"

# Enable Easy DKIM signing
aws ses set-identity-dkim-enabled \
  --identity "example.com" \
  --dkim-enabled

# Configure custom MAIL FROM domain
aws ses set-identity-mail-from-domain \
  --identity "example.com" \
  --mail-from-domain "mail.example.com" \
  --behavior-on-mx-failure UseDefaultValue
```

### D. Identity Details View (`/ses/identities/[identity]`)
Inspects identity overview, Easy DKIM CNAME DNS records, Custom MAIL FROM MX/TXT records, linked Amazon SNS notification topics, and access control policies.

**AWS CLI Equivalents:**
```bash
# Get DKIM tokens and verification status
aws ses get-identity-dkim-attributes \
  --identities "example.com"

# Get Custom MAIL FROM domain attributes
aws ses get-identity-mail-from-domain-attributes \
  --identities "example.com"

# Link Amazon SNS topic for bounce notifications
aws ses set-identity-notification-topic \
  --identity "sender@example.com" \
  --notification-type Bounce \
  --sns-topic "arn:aws:sns:us-east-1:000000000000:ses-alerts"

# Retrieve linked notification topics
aws ses get-identity-notification-attributes \
  --identities "sender@example.com"

# Set identity access policy
aws ses put-identity-policy \
  --identity "sender@example.com" \
  --policy-name "AllowSendEmail" \
  --policy '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"AWS":"*"},"Action":["ses:SendEmail"],"Resource":"arn:aws:ses:us-east-1:000000000000:identity/sender@example.com"}]}'

# Delete identity access policy
aws ses delete-identity-policy \
  --identity "sender@example.com" \
  --policy-name "AllowSendEmail"
```

### E. Configuration Sets (`/ses/configuration-sets`)
Manages configuration sets to control sending options and capture email telemetry.

**AWS CLI Equivalents:**
```bash
# Create configuration set
aws ses create-configuration-set \
  --configuration-set '{"Name": "transactional-alerts"}'

# List configuration sets
aws ses list-configuration-sets

# Describe configuration set
aws ses describe-configuration-set \
  --configuration-set-name "transactional-alerts"

# Delete configuration set
aws ses delete-configuration-set \
  --configuration-set-name "transactional-alerts"
```

### F. Email Templates (`/ses/templates`)
Creates, updates, and previews Mustache-rendered HTML and plain text email templates.

**AWS CLI Equivalents:**
```bash
# Create email template
aws ses create-template \
  --template '{"TemplateName": "WelcomeEmail", "SubjectPart": "Welcome, {{name}}!", "HtmlPart": "<h1>Welcome {{name}}</h1><p>Thanks for joining!</p>", "TextPart": "Welcome {{name}}! Thanks for joining!"}'

# List email templates
aws ses list-templates

# Get template details
aws ses get-template \
  --template-name "WelcomeEmail"

# Update email template
aws ses update-template \
  --template '{"TemplateName": "WelcomeEmail", "SubjectPart": "Welcome to our Cloud, {{name}}!", "HtmlPart": "<h1>Welcome to our Cloud!</h1>"}'

# Delete email template
aws ses delete-template \
  --template-name "WelcomeEmail"
```

### G. Send Test Email (`Send test email` Modal)
Dispatches formatted or raw test messages to individual recipients or the Amazon SES Mailbox Simulator.

**AWS CLI Equivalents:**
```bash
# Send standard formatted email
aws ses send-email \
  --from "sender@example.com" \
  --destination "ToAddresses=recipient@example.com" \
  --message "Subject={Data=Hello from Amazon SES},Body={Text={Data=This is a test email message.}}"

# Send templated email with dynamic JSON replacements
aws ses send-templated-email \
  --source "sender@example.com" \
  --destination "ToAddresses=recipient@example.com" \
  --template "WelcomeEmail" \
  --template-data '{"name": "Alice"}'
```

### H. Suppression List (`/ses/suppression-list`)
Inspects and manages the account-level recipient suppression list.

**AWS CLI Equivalents:**
```bash
# List suppressed email destinations
aws sesv2 list-suppressed-destinations

# Add address to suppression list
aws sesv2 put-suppressed-destination \
  --email-address "bounced-user@example.com" \
  --reason "BOUNCE"

# Remove address from suppression list
aws sesv2 delete-suppressed-destination \
  --email-address "bounced-user@example.com"
```

### I. SMTP Settings (`/ses/smtp`)
Views server connection details and generates dedicated IAM SMTP credentials using RFC 2104 HMAC-SHA256 password derivation.

**AWS CLI Equivalents:**
```bash
# Create IAM user for SMTP authentication
aws iam create-user \
  --user-name "ses-smtp-user.app1"

# Create access key
aws iam create-access-key \
  --user-name "ses-smtp-user.app1"

# Attach SES full sending permissions
aws iam attach-user-policy \
  --user-name "ses-smtp-user.app1" \
  --policy-arn "arn:aws:iam::aws:policy/AmazonSESFullAccess"
```

## 3. Hands-on Exercises for Beginners

### Exercise 1: Verify an Email Address and Send a Test Email
1. Navigate to **Verified identities** (`/ses/identities`) and click **Create identity**.
2. Select **Email address**, enter `dev-tester@example.com`, and click **Create identity**.
3. Confirm the identity displays a status of **Verified** in the identities inventory.
4. Click **Send test email**, choose scenario **Successful delivery (Mailbox Simulator)** (`success@simulator.amazonses.com`), and click **Send test email**.
5. **Expected Result**: A green banner confirms the email was accepted, displaying a unique returned `MessageId` (e.g. `0100aef75a43969a-0d94784a-...`).

### Exercise 2: Verify a Domain with Easy DKIM and Custom MAIL FROM
1. Navigate to **Verified identities** &rarr; **Create identity**.
2. Select **Domain** and enter `mycompany.org`.
3. Keep **Generate DKIM signatures (Easy DKIM)** checked.
4. Check **Use a custom MAIL FROM domain**, enter subdomain `mail`, and click **Create identity**.
5. In the created domain details, open the **Authentication** tab.
6. **Expected Result**: The console displays 3 CNAME records with host names matching `<token>._domainkey.mycompany.org` and targets `<token>.dkim.amazonses.com`, along with MX (`10 feedback-smtp.us-east-1.amazonses.com`) and SPF TXT record instructions.

### Exercise 3: Connect an Amazon SNS Topic for Bounce Notifications
1. Ensure you have an Amazon SNS topic created (navigate to `/sns` &rarr; Create topic `ses-bounces`).
2. Go to **Verified identities**, open `dev-tester@example.com`, and select the **Notification topics (SNS)** tab.
3. Click **Edit notification topics**.
4. In the **Bounce notification SNS topic** dropdown, select `ses-bounces` (loaded live from the emulator).
5. Click **Save changes**.
6. **Expected Result**: The bounce topic card updates to display `arn:aws:sns:us-east-1:000000000000:ses-bounces`.

### Exercise 4: Create and Preview a Templated Email
1. Navigate to **Email templates** (`/ses/templates`) and click **Create template**.
2. Enter Template name `OrderConfirmation`, Subject `Order Confirmation: #{{orderId}}`, HTML body `<h2>Thank you {{name}}!</h2><p>Your order #{{orderId}} is confirmed.</p>`, and Plain text `Thank you {{name}}! Your order #{{orderId}} is confirmed.`.
3. Click **Create template**.
4. Click **Preview** in the templates table to toggle between **HTML Rendered**, **HTML Source**, and **Plain text**.
5. **Expected Result**: The rendered preview displays the HTML markup with the replacement tags.

### Exercise 5: Generate SES SMTP Credentials
1. Navigate to **SMTP settings** (`/ses/smtp`).
2. Click **Create SMTP credentials**.
3. Enter an IAM username such as `ses-smtp-service` and click **Create**.
4. **Expected Result**: The modal returns the provisioned IAM User Name, SMTP Username (Access Key ID), and the calculated RFC 2104 HMAC-SHA256 SMTP Password with copy buttons and a `.csv` download option.

## 4. Limitations in the AWS Emulator

1. **No Outbound Internet Delivery**: The local emulator processes API calls, validates formats, updates counters, and emits real message IDs, but does not open external socket connections on port 25/587 to deliver emails to real external inboxes (such as personal Gmail or Yahoo addresses).
2. **Instant Identity Verification**: In real AWS, domain verification requires polling public DNS servers for TXT and CNAME records. The emulator immediately registers email and domain identities upon creation.
3. **Mailbox Simulator**: Test emails sent to `bounce@simulator.amazonses.com`, `complaint@simulator.amazonses.com`, and `success@simulator.amazonses.com` succeed via the emulator API and generate real Message IDs.
4. **Automated Route 53 Record Creation**: 1-click DNS record publishing requires Route 53 hosted zones. The console shows the exact manual DNS records required as in standard AWS console deployments.

## 5. Common Errors & Troubleshooting

### `MessageRejected: Email address is not verified`
* **Cause**: Sending an email from an email address or domain that has not been registered in Amazon SES while in Sandbox mode.
* **Fix**: Navigate to `/ses/identities/create`, verify the sender address or sending domain first, then re-send.

### `ValidationError: Value at 'behaviorOnMXFailure' failed to satisfy constraint`
* **Cause**: Specifying an invalid enum value for custom MAIL FROM failure policy.
* **Fix**: Use either `UseDefaultValue` or `RejectMessage`.

### `InvalidParameterValue: SNS topic <arn> is invalid`
* **Cause**: Attempting to attach an Amazon SNS topic ARN that does not exist in the emulator.
* **Fix**: Select an existing SNS topic from the dropdown or navigate to `/sns` to create one first.

### `TemplateDoesNotExist: Template <name> does not exist`
* **Cause**: Calling `SendTemplatedEmail` with a template name that has not been saved in the registry.
* **Fix**: Create the template under `/ses/templates` before referencing it in automated workflows.

## 6. Dependencies & Related Services

* [Amazon SNS](SNS.md): Captures automated delivery, bounce, and complaint notifications from verified identities and configuration sets.
* [AWS Key Management Service (KMS)](KMS.md): Encrypts messages and inbound email bodies at rest.
* [Amazon CloudWatch Logs](CloudWatch%20Logs.md): Ingests email delivery tracking and metric logs.
* [Amazon S3](S3.md): Stores inbound received email messages.
* [AWS IAM](../README.md): Authenticates SMTP credentials and manages identity resource delegation policies.
